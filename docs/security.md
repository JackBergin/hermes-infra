# Security and threat model

## Scope

Hermes can execute tools and ingest untrusted content. Docker packaging makes dependencies reproducible; it is not itself a security boundary against a sufficiently privileged agent.

The deployment protects against accidental loss of a single server's application state **only if** backups are stored outside that server and regularly restored. It does not protect against compromised host root, stolen backup encryption keys, malicious upstream images, or deliberate deletion by an administrator with full access.

## Boundaries and protections

1. **Secrets**: The root Compose `.env` contains only deployment settings. Hermes credentials are generated by Hermes into the ignored `state/.env`. Any archive containing that state is sensitive. Do not print/archive-upload it to public CI artifacts or Git LFS.
2. **Skills**: The reviewed Git-managed skills mount is read-only. Hermes native `skills.write_approval` is enabled by `make configure`. This is not a comprehensive defense against malicious skill code and it does not block local skills from shadowing external skills.
3. **Container**: Preserve the official s6 entrypoint for privilege drop and first-boot initialization. This stack does not expose `/var/run/docker.sock`, host credential directories, or API ports. It sets `no-new-privileges` but intentionally retains privileges needed by Hermes entrypoint initialization.
4. **Image**: Prefer a digest pin. Review Docker image provenance and Hermes upstream security announcements. Never accept untrusted image digests in automated upgrades.
5. **Backups**: The local ZIP is plaintext, stored mode 0600 under ignored `backups/`. Restic encrypts repository data with a password supplied through host environment/secret manager; protect the password and repository access separately.
6. **Restore**: An import overwrites matching Hermes files but may leave unrelated files in a non-empty target. Prefer a clean recovery host/state directory. Production restore is blocked on non-empty state by default.
7. **Permissions**: Hermes published images normally use container UID/GID 10000. The host bind mount may be inaccessible to the host login user, depending on filesystem ownership. Do not make sensitive state world-readable to work around this. Use documented UID/GID mapping when necessary.

## Security reporting

Please do not open a public issue containing API keys, private transcripts, or exploit payloads that expose others' systems. Contact the repository maintainer privately through GitHub profile channels for sensitive disclosures. This project has no formal security SLA.
